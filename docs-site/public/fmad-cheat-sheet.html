Foundry Method for Agile AI-Driven Development

Install once per project

$ npx skills add DavidBatoDev/fmad-method
  1. Pick your coding tool and skills. Include fmad, fmod-method, fmod-core-tools (or take them all).
  2. Open the tool in the project and say "fmad setup". It creates _fmad/ (config and scripts, commit it).
  3. Documents land in _fmad-output/, inside the active initiative's folder when one is set.

Three commands to remember

/fmad"What should I do next?" It inspects the project and recommends a skill.
/fmad-buildTurn a change into reviewed, verified code.
fmad statusVersions and what to run next. Say "fmad setup" again to update.

Needs an AI coding tool with skills (Claude Code, Codex, Cursor, and others), uv, Node.js, and Git.

Pick your path

New project

Small and clear: /fmad-build <what you want>

Clear, several sessions: spec → ticket → build per story → retrospective

Fuzzy idea: brainstorming or forge-idea → brief or PRD → UX and architecture → spec → tickets → builds

Hackathon: forge-idea → spec → build. Run fmad-project-context early.

Existing, no docs

Don't write docs first. Build reads the code and matches its conventions.

1. /fmad-project-context "set up AGENTS.md"

2. Small change: /fmad-build. Bigger: spec → ticket → build. Design: /fmad-architecture from the codebase.

3. Repeated mistake: "record: …". After big changes: "refresh".

Existing, with docs

1. /fmad-project-context "adopt our AGENTS.md". It keeps and improves what you have.

2. Feed docs to planning, not every build: /fmad-spec with sources (≤ 40 pages), PRD "update" or "validate", architecture from your doc.

3. Pin must-follow docs: persistent_facts in _fmad/custom/<skill>.toml (or ask /fmad-customize).

Tips

  • Unsure? Ask /fmad, for example "I have an existing Next.js app, where should I start?"
  • Break a pattern on purpose: say so in the fmad-build request. Otherwise Build matches what is already there.
  • Keep specs short: give fmad-spec condensed sources, not a pile of raw documents.
  • Planning in the browser: web bundles for Gemini Gems and ChatGPT GPTs are on the repo's Releases page.
  • Team vs. personal: _fmad/custom/*.toml is shared (commit it); *.user.toml is personal (git-ignored).

Every skill and what it can do

Invoke by name (/fmad-build …) or describe what you want

Hub and setup

SkillWhat it can doSay something like
fmadYour guide: answers FMAD questions, recommends the next skill, runs setup, status, update, and repair, and manages the active initiative"fmad setup" · "fmad status" · "what's next?"
fmad-project-contextWrites and maintains a small verified agent-instructions block in AGENTS.md: setup, adopt, refresh, record a pitfall, audit"set up AGENTS.md" · "record: agents keep using npm"
fmad-customizeWrites overrides that change how any skill or agent behaves: facts, principles, menus, hooks"customize fmad-build to run pnpm test"

Explore and research

fmad-brainstormingFacilitated ideation drawing on 100+ creative techniques, with an HTML keepsake of the session"help me brainstorm features for …"
fmad-forge-ideaPressure-tests a half-formed idea while personas probe its weak points, until it hardens or dies cheaply; can write a short brief"forge this idea: …"
fmad-deep-reconCited research for a decision: market, domain, technical, competitive, user voice, academic literature, or choosing between options. Runs it here, drafts a prompt for ChatGPT, Gemini, or Perplexity, or summarizes a report you bring"research the market for …" · "help me choose between A and B"
fmad-party-modeA roundtable between the agents or custom personas, including focus-group panels"party mode: should we build X?"
fmad-advanced-elicitationMakes the AI critique and improve its last answer with 70+ methods such as Socratic questioning, first principles, pre-mortem, red team"run a pre-mortem on that"

Define

fmad-product-briefCreates, updates, or validates a product brief: the vision on a page or two"create a product brief"
fmad-prfaqAmazon's Working Backwards: writes the launch press release first, then answers hard customer and stakeholder questions"work backwards on this idea"
fmad-prdCreates, updates, or validates a PRD, with an HTML validation report"create a PRD" · "validate the PRD"
fmad-specCondenses any input (idea, brief, PRD, transcript, notes) into a short spec that Build can execute; updates and validates specs"distill this into a spec"

Design

fmad-uxCaptures the UX in DESIGN.md (how it looks) and EXPERIENCE.md (how it behaves)"help me plan the UX"
fmad-architectureRecords the technical decisions that keep separately built parts consistent. Works from a spec, a raw idea, or an existing codebase"create the architecture"

Plan and track

fmad-ticketSlices initiatives into epics and epics into stories, writes and refines tickets, runs the board (publish, ready, move, assign, status) in the repo, GitHub, Jira, Linear, Notion, or Trello"break this epic into stories" · "what's ready?"

Build

fmad-buildThe workhorse: clarifies, plans (you approve), implements, reviews with independent reviewers, verifies, presents. Accepts an issue or story link"/fmad-build add dark mode"
fmad-build-autoOne unattended build iteration for automated loops, where an orchestrator hands each worker one ticketinvoke by name
fmad-qa-generate-e2e-testsGenerates API and end-to-end tests for features that already exist"create QA automated tests for checkout"

Review and verify

fmad-code-reviewSeveral independent reviewers check a change in parallel; findings are triaged before you see them"run code review"
fmad-reviewReview lenses for code or documents: adversarial, edge cases, verification gaps, structure, prose"review this PRD adversarially"
fmad-walkthroughWalks you through reviewing a commit, PR, file, or folder yourselfinvoke by name

Adjust and learn

fmad-correct-courseWhen a big change lands mid-build, assesses the impact on the PRD, epics, architecture, and UX and proposes the change"correct course: the client dropped payments"
fmad-retrospectiveEvidence-based review of a finished epic: sourced findings, action items, an acceptance decision"let's retro the epic"
